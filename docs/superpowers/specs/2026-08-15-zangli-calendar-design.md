# 藏历日历订阅设计

Date: 2026-08-15  
Status: Draft for user review

## Goal

做一个可公开订阅的藏历日历。用户用 Apple 日历、Google 日历、Outlook 等客户端订阅一个稳定的 ICS 地址，按公历年查看全年。

第一版生成 **公历 2026 年 1 月 1 日–12 月 31 日**，共 365 条全天事件。每天标题为「藏历×年×月×日」加上当天命中的短词；事迹、倍数、理发、食相说明只写在备注。只使用说明页已有规则和 `stonelf/zangli` 的公历／藏历转换与交食数据。说明页没有的会遇、宜忌、经幡、物候一律不写。

项目放在 `zangli-calendar/`，只用 GitHub 免费资源：仓库存源码和规则数据，Actions 生成 ICS，Pages 提供订阅地址。每年更新一次整年。运行时不访问外部网站。

## Architecture

```text
data/ 五表 + vendor/zangli/zangli.js
  → scripts/generate.js --year 2026
  → public/zangli-2026.ics
  → 覆盖 public/zangli.ics
  → 写 public/status.json
  → GitHub Actions 提交 public/ 并部署 Pages
  → 客户端订阅稳定 URL
```

对外地址：

```text
https://<github-user>.github.io/zangli-calendar/zangli.ics
https://<github-user>.github.io/zangli-calendar/zangli-2026.ics
https://<github-user>.github.io/zangli-calendar/status.json
```

`zangli.ics` 是稳定订阅地址，每年整年重生成后覆盖。`zangli-2026.ics` 是当年存档。

转换脚本从 [stonelf/zangli](https://github.com/stonelf/zangli) 纳入 `vendor/zangli/`，保留 MIT 许可证原文。生成时只读这份本地文件，不在运行时拉取 GitHub 或素食加盟站。

## Rule Data

数据全部按藏历月日，不按公历。闰日不套佛日、功德、八吉、九凶；理发仍按该日序写。闰月按所闰之月的月序查表。

与说明页对齐时按栏目各取可执行句，不把「起源」段的十亿倍和「功德倍增日月表」的乘积混成一套数：功德表列出的月日写表内乘积；四大节日与日食月食另写十亿倍。两者可以同一天同时出现。

## Event Composition

每天一条全天事件，日期按北京时间对应的公历日。不占忙闲（`TRANSP:TRANSPARENT`）。

`getZangli` 给出年名（如「火马」）、月名（「正」…「十二」，闰月带「闰」）、日序（「初四」「廿九」，闰日带「闰」）。标题里的月写成数字：正月→`1`，十一月→`11`。闰月写成 `闰7` 这种形式。日序保留汉字，闰日保留「闰」字。

### Title

```text
藏历{年名}年{月数字}月{日序}
```

命中短词时，用全角空格接在日期后，顺序固定：

1. `闰日`（仅 `dayLeap`）
2. 交食类型原文（`日全食`、`月偏食` 等，来自 `getEclipse().value`）
3. 专名节日，仅当 `extraInfo`（去掉 `<br>`）属于下列白名单：`神变节`、`释迦牟尼佛诞辰`、`释迦牟尼佛成道日涅槃日`、`释迦牟尼佛入胎日`、`释迦牟尼佛初转法轮日`、`释迦牟尼佛天降日`。有专名则不再写第 4、5 项
4. 否则初十写 `莲师日`
5. 否则按上表「何时写佛名短词」写：`等持如来日`、`药师如来日`、`贤劫千佛日`、`阿弥陀佛日`、`观世音菩萨日`、`地藏菩萨日`、`空行荟供日`、`释迦牟尼佛日`。初十已由第 4 项覆盖，不写「莲花生大师日」
6. `功德倍增`：该月在 `merit-months.json`、该日在 `merit-days.json`、且非闰日
7. `八吉同聚`
8. `九凶同聚`

理发不进标题。普通日标题只有藏历日期。缺日预告不进标题，只写在前一天的备注。

`禅定胜王佛节日`、`莲师荟供日`、`药师佛节日`、`阿弥陀佛节日` 等不在白名单内的 `extraInfo` 不直接进标题，分别归入第 4 或第 5 项的固定短词。七月初一的 `禅定胜王佛节日` 因当月不在功德表，标题不写「等持如来日」。

闰日不套第 3–8 项。`zangli.js` 对闰日本来也不给 `extraInfo`。

**四大节日**（起源「十亿倍」适用对象，与专名白名单不是同一集合）仅这四个：`神变节`、`释迦牟尼佛成道日涅槃日`、`释迦牟尼佛初转法轮日`、`释迦牟尼佛天降日`。诞辰、入胎只作专名短词，不写十亿倍。

### Description

有则写，无则整段省略。段与段之间用换行。顺序：

1. 闰日：`闰日（守戒取第一天）`
2. 缺日预告：若次一公历日与本日同属一个藏历年、月，且次日日序（去掉「闰」）≥ 本日日序＋2，则中间缺的那一日写在本日。句式：`本日之后缺{日序}，守戒可提前于本日`。例：本日十四、次日十六 → `本日之后缺十五，守戒可提前于本日`。缺日本身没有公历日，不另造事件。`getZangli().dayMiss` 落在缺口之后那天，备注不得写在那天，必须写在缺口前一天
3. 交食：`{类型}（{extraInfo}）`；若 `getEclipse().extraInfo2` 非空（有初亏／复圆时 zangli.js 会把食甚放到 `extraInfo2`），写成 `{类型}（{extraInfo}，{extraInfo2}）`，避免漏掉食甚时间。例：2026-03-03 月全食 → `月全食（初亏17点49分，复圆21点17分，食甚19点34分）`
4. 十亿倍：起源「四大节日和日食、月食」。只命中交食写 `日食月食日行持善法功德呈十亿倍增上`；只命中四大节日写 `四大节日行持善法功德呈十亿倍增上`；两者同一天写 `四大节日及日食月食日行持善法功德呈十亿倍增上`
5. 莲师应化：仅初十且非闰日。`莲师应化：`＋当月事迹全文
6. 功德倍增：仅标题第 6 项命中时。`功德倍增：{月名}{月倍中文}倍×{日名}{日倍中文}倍`。倍数写成与说明页相同的中文（`100`、`1000`、`1万`、`10万`、`100万`、`1000万`、`1亿`、`9亿`、`10亿`、`1000亿`），不计算超大乘积。不替代上一则十亿倍
7. 八吉同聚：`八吉同聚，无论从事何事都吉祥`
8. 九凶同聚：`九凶同聚，无论从事何事都不吉，尤其忌讳嫁娶`
9. 理发：`理发：`＋`hair.json` 当日条文。每天都有

缺日预告补充：某月月末缺日（`zangli.js` 数据里为 `-30`）时，该月止于廿九、次日即下月初一，上面第 2 条的同月判断不会触发；遇此情形在廿九写 `本日之后缺三十，守戒可提前于本日`。2026 年无 `-30`，此条为以后年份预留。

## ICS Fields

日历头：

```text
BEGIN:VCALENDAR
PRODID:-//zangli-calendar//zh-CN//CN
VERSION:2.0
CALSCALE:GREGORIAN
METHOD:PUBLISH
X-WR-CALNAME:藏历
X-WR-CALDESC:公历年藏历订阅。规则取自藏教日历说明与 stonelf/zangli。
X-WR-TIMEZONE:Asia/Shanghai
```

每条事件：

| ICS 字段 | 值 |
|---|---|
| `UID` | `zangli-YYYYMMDD@zangli-calendar`，按公历日固定 |
| `DTSTAMP` | 本次生成时刻，UTC |
| `DTSTART;VALUE=DATE` | 公历日，如 `20260816` |
| `DTEND;VALUE=DATE` | 次日，如 `20260817` |
| `SUMMARY` | 标题 |
| `DESCRIPTION` | 备注；按 RFC 5545 转义换行与特殊字符 |
| `TRANSP` | `TRANSPARENT` |

缺日没有对应公历日，不另造事件。2026 不是闰年，必须正好 365 条 `VEVENT`。

## Generation and Publishing

```text
node scripts/generate.js --year 2026
```

生成脚本必须在 `Asia/Shanghai` 时区运行：`generate.js` 开头设 `process.env.TZ = 'Asia/Shanghai'`，工作流 `env` 同时设 `TZ: Asia/Shanghai` 双保险。`zangli.js` 的 `getEclipse` 用本地时区把食相映射到公历日并计算食甚时间；在 runner 默认 UTC 下，2026-08-13 日全食会错落到 8 月 12 日、2026-02-17 日环食的食甚会写成「12点13分」而非北京时间「20点13分」。

按该公历年每一天调用 `compose-day`，再 `build-ics`，写入：

- `public/zangli-2026.ics`
- `public/zangli.ics`（与当年文件内容相同）
- `public/status.json`

```json
{
  "year": 2026,
  "event_count": 365,
  "generated_at": "2026-08-15T00:00:00Z",
  "calendar_url": "https://<github-user>.github.io/zangli-calendar/zangli.ics",
  "archive_url": "https://<github-user>.github.io/zangli-calendar/zangli-2026.ics"
}
```

GitHub Actions 工作流 `.github/workflows/generate-calendar.yml`：

- `workflow_dispatch`，输入 `year`，默认当前公历年
- `schedule`：`0 0 1 1 *`（1 月 1 日 UTC），生成刚开始的这一公历年
- 步骤：检出 → `actions/setup-node` → `npm test` → `node scripts/generate.js --year <year>` → 提交 `public/` → 部署 Pages；工作流 `env` 设 `TZ: Asia/Shanghai`

权限与世界杯日历相同：`contents: write`、`pages: write`、`id-token: write`。无 runtime secret。

第一次上线生成 2026 全年。生成器用 `--year` 支持以后各年，不在第一版同时发布 2027。年份必须落在 `zangli.js` 可转换区间内（约 1951–2050），否则失败。

`status.json` 里的 Pages 地址在实现时写入实际仓库所属用户名，规格里的 `<github-user>` 不是运行时占位符。

## Error Handling

以下任一情况必须使本次生成失败，且不部署、不覆盖 Pages 上的上一份成功文件：

- 任一天 `getZangli` 返回 `error` 或缺少年／月／日
- `VEVENT` 条数不等于该公历年天数
- `data/` 任一规则文件缺失、无法解析，或缺月／缺日条目（头发品必须 1–30 齐全）
- 纳入的 `zangli.js` 不存在，或用 Node `vm` 加载后得不到 `getZangli`／`getEclipse`（该文件是浏览器脚本，不是 ES 模块）
- 生成文本缺少 `BEGIN:VCALENDAR`／`END:VCALENDAR`

失败时 Actions 红灯。不在本项目里自动开 Issue。
